# MG Floor — local Android builds (no EAS)

Use this path for **factory tablet APKs** and **Play Store AABs** without Expo Application Services.

Related: [MG-FLOOR.md](./MG-FLOOR.md), Nexa equivalent [MOBILE-ANDROID-LOCAL-BUILD.md](./MOBILE-ANDROID-LOCAL-BUILD.md).

## Prerequisites

- Node 24.x, JDK 17+, Android SDK / Android Studio
- `EXPO_PUBLIC_API_URL` set for the target environment (do not point production APKs at localhost)

## First time — generate native project

```bash
# from repo root
set EXPO_PUBLIC_API_URL=https://api.loopcstrategies.com
npm run mg-floor:prebuild:android
```

Or from `mg-floor/`:

```bash
npm run prebuild:android
```

This creates `mg-floor/android/` (Gradle wrapper). Re-run after changing native plugins in `app.config.ts`.

## Factory tablets — release APK (sideload)

**Windows (recommended if Desktop paths hit MAX_PATH):**

```bat
scripts\build-mg-floor-apk-subst-q.cmd
```

**Any OS / short path:**

```bash
npm run mg-floor:build:android:local:apk
```

Output:

`mg-floor/android/app/build/outputs/apk/release/app-release.apk`

Install on the phone/tablet (allow unknown sources). The APK is signed with the MG Floor release key (see **Release signing** below). Without it, the build scripts fall back to **debug signing** (internal QA only).

## Play Store later — AAB

```bash
npm run mg-floor:build:android:local:bundle
```

Output:

`mg-floor/android/app/build/outputs/bundle/release/app-release.aab`

Upload in Google Play Console (enrol in Play App Signing; this key is the upload key).

## Release signing

`mg-floor/android/` is regenerated by prebuild, so signing is injected by the config plugin `mg-floor/plugins/withReleaseSigning.js`. It reads:

| File (gitignored) | Content |
|-------------------|---------|
| `mg-floor/credentials/mg-floor-upload.jks` | Upload keystore (PKCS12, alias `mg-floor-upload`, RSA 2048, valid 10000 days) |
| `mg-floor/credentials/keystore.properties` | `storeFile`, `storePassword`, `keyAlias`, `keyPassword` (template: `keystore.properties.example`) |

- **Back up both files now** (password manager / offline encrypted storage). If the key is lost, a published app cannot be updated with the same package ID.
- Never commit them. A new machine needs a copy of both files in `mg-floor/credentials/`.
- Without `keystore.properties`, Gradle refuses release builds unless `-PallowDebugReleaseSigning=true` is passed (the local build scripts do this automatically, with a warning). EAS builds keep using EAS-managed credentials.
- Check the signature: `apksigner verify --print-certs app-release.apk` must show `CN=MG Floor`, not `Android Debug`.

## Daily development (no APK)

```bash
cd mg-floor
set EXPO_PUBLIC_API_URL=http://localhost:5000
npm start
# or
npm run android
```

Metro / `expo run:android` does **not** use EAS credits.

## What does not use EAS

| Command | EAS? |
|---------|------|
| `npm run dev:mg-floor` / `expo start` | No |
| `mg-floor:prebuild:android` | No |
| `mg-floor:build:android:local:apk` | No |
| `mg-floor:build:android:local:bundle` | No |
| `eas build` / `eas update` | Yes — skip for MG Floor |
